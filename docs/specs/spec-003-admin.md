## 背景

- 对应 P0 故事：**US-08**（账号登录）、**US-09**（3D 场景内拖拽布放）、**US-10**（上传/替换模型与资料）、**US-11**（保存即生效）；覆盖 P1 故事 US-12（显隐/移除不删数据）、US-13（成果库布放状态）。
- 界面依据：`information-architecture.md` 的 UI-04 管理登录页、UI-05 布放编辑模式、UI-06 成果库（档案弹窗）。
- 数据依据：`data-model.md` 五表（admin_user / scene / achievement / achievement_media / placement）。
- 现实缺口：V07 的 22 项成果中**只有 6 项已布展**，其余 12 项模型齐备、照片齐全，只缺“摆上去”的能力——本 SPEC 交付这个能力。

## 范围

1. **登录**：右上「管理入口」→ 登录页 → 账号密码（bcrypt 存储）→ 进入编辑模式；错误提示；连续失败延时；会话（JWT 或 cookie）默认 7 天；退出编辑回到观众视图。
2. **布放编辑模式**：顶栏工具条（成果库 / 保存 / 退出编辑）；选中成果出现包围框与移动箭头 + 旋转圆环；拖拽调整 `position(x,z)` 与 `rotation_y`；吸附到最近展台/桌面（surface 吸附优先，空地为自由摆放）；未保存改动提示，离开前 `Modal.confirm` 拦截。
3. **成果库（档案弹窗）**：左列表（22 项：缩略图/名称/类别/规格）+ 右档案（实景照片、简介、特征）；「上传新成果」（.glb/.gltf + 图片/视频资料 + 名称/类别/编号）与「替换模型 / 资料」；「放入场景」把选中成果加入编辑场景（默认出现在选中台面）。
4. **保存即生效**：保存把当前布放写入 `placement` 表并广播给观众端（观众刷新/下次进入即最新）；单管理员单场景，无发布审核流。
5. **显隐/移除（P1）**：从场景移除某成果 = 删除其 placement 记录（成果本体保留在库中）；可选“暂时隐藏”。
6. **素材与既有资产**：直接使用 spec-002 的 catalog（22 项，含 12 项未布展）；环境贴图沿用现有，不重做。

## 明确不做

- 多管理员/角色分权、注册、找回密码（凭据线下重置）。
- 审批/发布流、版本回滚（V1 单管理员直接生效）。
- 成果功能动画与交互仿真（V2，US-17 P2）。
- 移动端适配（US-07 P1）、观察点/平面定位（US-14/15 P1）。
- 模型实时减面/自动优化：上传的 glTF 按原样存储与加载（超大模型给提示，不自动处理）。

## 验收标准

- [ ] 观众端右上「管理入口」→ 输入正确账号密码 → 进入编辑模式（顶栏出现工具条）；错误密码有明确提示。
- [ ] 编辑模式下选中场景中已布放的成果 → 出现包围框与手柄；拖拽后位置/朝向变化，观众端不可见直至保存。
- [ ] 从成果库把「数字孪生智慧检测系统」放入空余展台 → 保存 → 刷新观众页，该成果出现在场景与左栏目录（第 7 项起）。
- [ ] 上传一个新成果（.glb + 封面图 + 简介）→ 出现在成果库列表 → 放入场景并保存成功。
- [ ] 替换某成果模型文件 → 场景中该成果即时更新，名称/资料不变。
- [ ] 移除已布放成果 → 场景消失、成果库仍在（未布放状态）；不删成果数据。
- [ ] 未保存时点「退出编辑」→ 弹确认；取消则留在编辑模式。
- [ ] 保存失败（模拟断网）→ 明确报错且不丢失本地改动，可重试。
- [ ] 未登录直接访问编辑 API 返回 401；观众端接口不暴露写能力。
- [ ] 观众端在编辑期间不受影响（另一浏览器窗口浏览正常）。

## 技术要点

- 后端 NestJS + PostgreSQL：`POST /auth/login`、`GET/POST/PUT/DELETE /placements`、`GET/POST/PUT /achievements`、文件上传（本地盘 `/data/uploads`，DB 存 URL）。
- 前端：登录态存 localStorage（JWT）；编辑态复用现有 R3F 场景，加入 TransformControls（drei）+ 吸附逻辑；保存后强制刷新 catalog 数据。
- 数据迁移：`catalog.json` 的 22 项 + 6 条 placement 作为种子导入 PG（seed 脚本一次执行）。
- 资产：上传的 glb 需≤50MB、贴图≤4K，超出提示（不自动压缩）。

- **保存**：写 `localStorage['lm-layout-v1']`（`{id:{x,z,rotY}}`），刷新后仍生效；观众端读同一份布局。

## 补充（2026-11-21）：成果资产替换

- 入口：成果库选中成果后，底部出现「替换模型 / 替换照片 / 恢复原模型」。
- **替换模型**：选择 `.glb`，写入 IndexedDB（`laomo-assets/models`）并即时替换场景中该成果的全部子网格；新模型自动归一化（高度 0.42m）并贴台面/地面。
- **替换照片**：选择图片，转 dataURL 存 `photos` 表，成果库缩略图与介绍浮层立即更新，刷新后仍生效。
- **恢复原模型**：删除本地记录并重载页面，回到 GLB 自带模型。
- 存储说明：V1 为纯前端方案（IndexedDB），换设备/换浏览器不共享；接后端后改为上传到服务端并写入 `achievement.model_url` / `photo_url`。
- 验证状态：面板与按钮布局已截图确认；文件选择与解析流程未做自动化验证（浏览器自动化无法操作系统文件选择框），需人工试一次。

## 补充（2026-11-21）：最小后端已落地

`server/index.mjs`（Express + multer，端口 3001，数据落 `server/data/`）：

| 接口 | 鉴权 | 说明 |
|---|---|---|
| `POST /api/login` | 否 | scrypt 校验，返回 7 天期 HMAC 签名令牌 |
| `GET /api/layout` | 否 | 观众端读取布放，保证所有人看到同一套布置 |
| `PUT /api/layout` | 是 | 管理员保存布放 |
| `GET /api/assets` | 否 | 已替换模型/照片的映射表 |
| `POST /api/assets/:id/model` | 是 | 上传 glb（≤80MB），覆盖旧文件 |
| `POST /api/assets/:id/photo` | 是 | 上传照片 |
| `DELETE /api/assets/:id` | 是 | 恢复原模型/照片 |

前端行为：
- 登录优先调用后端；**后端未启动时降级为本机演示口令**并在弹窗提示。
- 布放保存：写后端成功提示"已同步服务端"，失败退回本地缓存（localStorage）并提示。
- 模型/照片替换：有令牌则上传到服务端并通过 `/uploads/...` 拉取；无令牌退回 IndexedDB。
- 启动时先读 `GET /api/assets`（照片/模型）与 `GET /api/layout`，服务端数据优先于本地缓存。

验证记录：`health`、登录成功/失败（401）、带令牌 PUT、无令牌 PUT（401）、上传（返回 `/uploads/xxx.glb`）、静态访问（200）、DELETE 清理，均用 curl 实测通过；浏览器端页面渲染正常。
