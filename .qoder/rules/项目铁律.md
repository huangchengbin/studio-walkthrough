# LaoMoSHi_show · 项目铁律

> 与仓库根目录 `AGENTS.md` 同源。两者冲突时，以本文件为准（Qoder 规则优先级高于 AGENTS.md）。
> 任何 AI 进入本仓库，先读这一份，再动手。

## 1. 单一事实来源

- 同一个产品设定只允许在一个文档里描述。
- 禁止在两个文档重复描述同一件事，禁止写"近似但不一致"的两份内容。
- 修改前先检索 `docs/` 全部文档；改完必须同步所有受影响位置。
- 发现两份文档冲突：停下来报告，由人决定以哪份为准。

## 2. 文档分层

```
docs/product/overview.md                 定位、一句话描述、做什么/不做什么
docs/product/users-and-stories.md        角色、用户故事、P0/P1/P2
docs/product/information-architecture.md 界面清单、每屏信息层级、主操作
docs/product/data-model.md               表、字段、表关系
docs/product/tech-stack.md               技术选型与理由
docs/product/design.md                   视觉规范（组件/风格/布局）
docs/engineering/workflow.md             git、测试、合并、发布
docs/specs/spec-xxx.md                   单轮开发的需求规格说明书
```

禁止往 `src/` 放产品文档；禁止在 `docs/` 之外新建产品说明文件。

## 3. SPEC 驱动

- 任何功能开发前，先产出 `docs/specs/spec-<三位编号>-<短名>.md`。
- SPEC 必含：背景、范围、验收标准、明确不做什么。
- 开发按 SPEC 执行；验收按 SPEC 逐条打勾。
- SPEC 之外的需求，先补 SPEC 再动工。

## 4. Git 流程

- 每次从 `main` 拉 `feature/<短名>` 分支，只在分支上提交业务代码。
- 禁止直接在 main 上开发；main 永远可运行。
- 测试通过后才合并回 main。

## 5. 远端备份

- `main` 推送到 GitHub 远端；每次合并后推送。
- 每完成一个阶段打 tag（如 `stage-1-product-foundation`）。

## 6. 阶段汇报

每完成一个阶段输出：改了哪些文档（路径 + 一句话原因）、是否有冲突待拍板、下一步一个推荐方案。
